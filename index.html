How People Use Falcon in Real Life: Plain Signatures vs. Sealed Envelopes

In real computer systems, Alice and Bob can use Falcon in two simple ways:

OPTION 1 · PLAIN SIGNATURE
Like a Signed Public Contract

Alice broadcasts a public message alongside her signature. Anyone on the internet can read the message, and anyone can check that Alice really wrote it. It is not private, but it is 100% authentic and impossible to forge.

OPTION 2 · SIGN-THEN-ENCRYPT
Like a Signed Letter in a Sealed Lockbox

Alice signs her message with Falcon, then locks both the message and the signature inside a quantum-safe encrypted box (using ML-KEM / Kyber). Eavesdroppers only see gibberish; only Bob can unlock the box and verify Alice's signature.

STAGE 01 • PRIVATE KEYGEN
Trapdoor Generation

Alice generates secret polynomials f, g ∈ [-15, +15], solves NTRU equation f·G - g·F = q to find trapdoor F, G, and broadcasts public key h = g·f⁻¹ (897 Bytes).

STAGE 02 • GAUSSIAN SIGNING
Lattice Rounding

Alice hashes message HashToPoint(r||M) → c, navigates the LDL tree with FPU emulation, samples short vector (s₁, s₂), and compresses s₂ into a 666-byte packet.

STAGE 03 • UNTRUSTED CHANNEL
Threat Model & Eve

Public key h and packet [M, r, s₂] traverse the network. If adversary Eve alters even 1 bit of the message or signature, she cannot forge a valid vector without trapdoor basis (f,g,F,G).

STAGE 04 • HARDWARE VERIFY
Euclidean Norm Bound

Bob multiplies p = s₂·h in 60k cycles, recovers s₁ = c - p, and squares all coefficients. If σ ≤ 34,034,726, the signature is 100% genuine; otherwise, it is instantly rejected.

2. The Mathematical Walkthrough: Alice Signs & Bob Verifies

ACT 1 · ALICE CREATES HER KEYS (KEYGEN)

Solving the NTRU Equation: f·G - g·F = 12289

Alice rolls random dice to generate two tiny secret polynomials with small 8-bit coefficients:

f = [-26, -7, -32, -7, -1, -38, 38, -23]
g = [-36, 25, 8, 15, 75, -12, 17, 39]

Using the extended Euclidean algorithm, Alice's computer finds large partner polynomials \(F\) and \(G\) that satisfy the famous NTRU equation:

F = [83, 24, 0, -74, 82, 32, 38, 28]
G = [14, 16, -6, -13, 19, 36, -3, -10]
Math Check: f·G - g·F = [12289, 0, 0, 0, 0, 0, 0, 0] ≡ 12289 (Exact match!)

Finally, Alice computes her Public Key \(h = g \cdot f^{-1} \pmod{12289}\) using fast NTT multiplication:

Public Key h = [3178, 7201, 3796, 8969, 1583, 2472, 1521, 8339] (8 numbers, 14-bits each)

Alice uploads \(h\) to her public directory. She stores \(\{f, g, F, G\}\) secretly inside her private hardware enclave.

ACT 2 · ALICE SIGNS HER CHAT MESSAGE (SIGN)

Target Point c & Fast Fourier LDL Sampling

Alice types her chat message: M = "Falcon toy demo". Her computer generates a 40-byte random nonce salt:

Salt r = "19cb644de108a284692a2fe6f27881f3fcd037f5152d9a1275d057e97c9343cff064ff057f24a4bc" (40 Bytes / 320 bits)

Alice hashes \(r \parallel M\) using SHAKE-256 (HashToPoint) to yield target vector \(c\):

Target Point c = [8984, 7047, 6563, 4376, 6769, 5373, 11990, 6291] (All numbers mod 12289)

Using her secret trapdoor \(\{f, g, F, G\}\), Alice computes the continuous target coordinates \((t_0, t_1) = (-c F / q, \, c f / q)\):

t0 = [ 12.17, -55.38, 28.93, 116.96, -6.08, -33.63, -140.71, -113.69]
t1 = [ 25.84, 23.30, -32.86, -2.82, -46.22, -55.72, -31.32, -53.66]

Alice's chip passes \((t_0, t_1)\) through the m21_samplerz Gaussian randomizer to sample integers \((z_0, z_1)\), and constructs signature vector \(s_2 = z_0 f + z_1 F \pmod{12289}\):

Signature Vector s2 = [-227, -138, -86, -106, 24, -101, -89, 137]

Alice packages \(\{M, r, s_2\}\) and sends it over the internet to Bob.

ACT 3 · BOB VERIFIES ALICE'S SIGNATURE (VERIFY)

Distance Check: ||(s1, s2)||² ≤ 463,174

Bob receives the chat message M = "Falcon toy demo", salt \(r\), and signature \(s_2\). Bob does NOT know Alice's secret key! He only has Alice's public key \(h\).

Step 1: Bob recomputes target \(c = \text{HashToPoint}(r \parallel M)\):

c = [8984, 7047, 6563, 4376, 6769, 5373, 11990, 6291]

Step 2: Bob multiplies \(p = s_2 \cdot h \pmod{x^8 + 1} \pmod{12289}\) using fast NTT:

p = [9122, 7296, 6495, 4467, 6920, 5324, 11720, 6453]

Step 3: Bob recovers \(s_1 = (c - p) \pmod{12289}\), centered into the range \([-6144, +6144]\):

s1[0] = 8984 - 9122 = -138
s1[1] = 7047 - 7296 = -249
s1[2] = 6563 - 6495 = 68
s1[3] = 4376 - 4467 = -91
s1[4] = 6769 - 6920 = -151
s1[5] = 5373 - 5324 = 49
s1[6] = 11990 - 11720 = 270
s1[7] = 6291 - 6453 = -162
Reconstructed s1 = [-138, -249, 68, -91, -151, 49, 270, -162]

Step 4: Bob computes the total squared Euclidean distance:

||s1||² = (-138)² + (-249)² + 68² + (-91)² + (-151)² + 49² + 270² + (-162)² = 218,295
||s2||² = (-227)² + (-138)² + (-86)² + (-106)² + 24² + (-101)² + (-89)² + 137² = 126,673
Total Distance² σ = 218,295 + 126,673 = 344,968
Bullseye Threshold ⌊β²⌋ = 463,174
Verdict: 344,968 ≤ 463,174 → VERIFIED AUTHENTIC! (Bob accepts!)
ACT 4 · ATTACKER EVE INTERCEPTS & TAMPERS (BLOWUP DEMO)

Eve Changes 1 Letter: Distance Explodes 240x!

Suppose an adversary Eve intercepts the transmission and alters just a single letter, changing "Falcon toy demo" to "Falcon toy demO" (lowercase 'o' to uppercase 'O').

Because SHAKE-256 has the avalanche effect, changing one letter produces a wildly different target point \(c_{\text{fake}}\):

c_fake = [4292, 199, 11775, 9100, 8601, 3333, 9900, 5373] (Completely uncorrelated!)

Bob calculates \(s_1 = (c_{\text{fake}} - p) \pmod{12289}\):

s1[0] = 4292 - 9122 = -4830 (Blew up from -138!)
s1[1] = 199 - 7296 = -7097 ≡ +5192 (Blew up from -249!)
s1[2] = 11775 - 6495 = +5280 (Blew up from 68!)
Reconstructed fake s1 = [-4830, 5192, 5280, 4633, 1681, -1991, -1820, -1080]

Bob computes the distance squared:

||s1_fake||² = (-4830)² + 5192² + 5280² + 4633² + 1681² + (-1991)² + (-1820)² + (-1080)² = 110,897,495
Total Distance² σ = 110,897,495 + 126,672 = 111,024,167
Bullseye Threshold ⌊β²⌋ = 463,174
Verdict: 111,024,167 >> 463,174 (240x LIMIT BLOWUP!) → REJECTED: FAKE DETECTED!

Bob immediately blocks the packet and sounds the alarm. Even with a quantum supercomputer, Eve cannot produce a valid signature without Alice's secret key!

How Lattice Security Works

Think of signing a message like throwing a dart at a dartboard. Alice has a secret straight ruler that lets her find the closest bullseye in a microsecond. An attacker only has a warped, twisted ruler that makes finding the bullseye practically impossible!

Alice's Secret Grid (Clean, straight shortcut)
The Public Grid (Warped and twisted for attackers)
Target Point c (Where the message landed)
The Green Bullseye (Allowable distance limit)
Alice's Signature Point (Lands safely inside bullseye)
Why add random noise? If Alice always picked the exact nearest grid point, a smart attacker watching 10,000 signatures could figure out her secret key. Falcon adds a tiny bit of random noise (like a gentle breeze) so her secret shortcut remains 100% hidden!

The Big Chip Problem: Why Normal Math Failed

How Thomas Pornin solved Falcon's math using plain integers, and how our hardware design split it across 6 chip multipliers.

CHIP MODULE: m13_fpu64.sv
PROBLEM 1 · THE WOODEN RULER

Why Fixed-Point Math Failed

Imagine trying to measure the distance to the moon and the thickness of a human hair with the same wooden ruler!

  • Crazy Number Range: Falcon calculates numbers that are both astronomically huge and unimaginably tiny.
  • Rounding to Zero: Standard fixed-point decimals rounded the tiny numbers down to zero, causing math errors and crashes.
  • Security Broken: Trying to fix this by adjusting the scale on the fly ruined the mathematical security proofs.
PROBLEM 2 · THE STOPWATCH SPY

Pornin's Constant-Time Fix (fpr)

Normal computer chips calculate strange numbers slightly slower. Hackers with a stopwatch can time those microsecond delays to steal secret keys!

  • Plain Whole Numbers: Pornin packed 64-bit decimal numbers into standard integers (uint64_t).
  • No 'If-Else' Decisions: The math uses only bitwise operations with zero conditional branches.
  • Clock-Locked Speed: It takes the exact same number of clock ticks every single time. No stopwatch can spy on it!
OUR SILICON CHIP SOLUTION

6 Multipliers in 5 Clock Ticks

How do we multiply giant 53-bit numbers on a real FPGA chip without building a giant, hot circuit? We split the math formula:

P = 2¹⁰⁴ + 2⁵²(m_a + m_b) + m_a · m_b

By cutting the numbers into 3 pieces each, exactly 6 small hardware multipliers (DSP48E2 slices) do the whole job in just 5 clock cycles!

The 6 Pillars of the Falcon Silicon Core

01 · High-Dimensional Grid (Lattice)

All math lives inside a 512-dimensional grid of numbers wrapped around clock modulus 12289. Finding shortcuts through this grid is easy for Alice, but mathematically impossible for any supercomputer or quantum machine.

f·G - g·F ≡ 12289 (mod xⁿ + 1)

02 · Random Noise Engine (SamplerZ)

Adds gentle, random bell-curve noise to every signature. This creates a protective fog that stops hackers from studying thousands of Alice's signatures to reverse-engineer her private key.

Bell Curve Randomizer in Silicon

03 · Clock-Locked Math Engine (FPU)

A custom 64-bit math processor in m13_fpu64.sv with zero conditional branches. It always finishes in the exact same number of clock ticks, making it 100% immune to stopwatch timing attacks.

6 Multipliers @ Fixed 5-Cycle Latency

04 · Traffic Controller RAM (Scoreboard)

An intelligent memory coordinator in m14_vram.sv that tracks data dependencies. It stops data collisions and pipeline stalls when reading and writing chip memory at high speeds.

Zero-Stall Dual-Port RAM Controller

05 · Smart Tree Walker (Memory Saver)

A microcoded sequencer that climbs Falcon's mathematical tree step-by-step as needed. This saves over 120 expensive chip memory blocks by streaming nodes instead of storing the entire tree at once.

Streaming Tree Sequencer

06 · Supercharged Multiplier (NTT)

The math equivalent of high-speed fiber optics. It converts massive polynomial multiplications into instant point-by-point operations, speeding up signature verification by more than 100x.

O(n log n) Fast Butterfly Math
